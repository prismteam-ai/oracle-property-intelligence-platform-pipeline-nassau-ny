# Town of Oyster Bay eTRAKiT permit harvest

Source: `https://oys-trk.aspgov.com/eTRAKiT/` (CentralSquare eTRAKiT), operator-supplied public account (credentials in the gitignored `.env`; never printed, logged or committed, and scrubbed from every saved page, including the account holder's display name).
Access rules followed: one browser action at a time; only actions that send a request are paced (at least 1 s apart); exponential backoff; stop and record on any captcha, 403/429, block or lockout wording (none seen in any run so far).

## How the portal behaves (verified)

- Login on `login.aspx` has no captcha. The permit search page loads Google's reCAPTCHA script but its challenge panel stays empty; the harvester stops if it ever fills or a captcha/challenge iframe appears.
- Search by **SECTION-BLOCK-LOT** or **PERMIT NUMBER** with Begins With / Contains / Equals / At Least / At Most. Block-level search `46-334-` returns every permit in that block. Grid shows permit number, section-block-lot (unpadded, e.g. `46-334-11`) and a hidden record id; 20 rows a page.
- **One click on a result row returns every detail tab in a single request**: Permit Info (type, subtype, job description, status, applied/approved/issued/finaled/expiration dates), Site Info (address, PARID, section, block, lot, lot size), Contacts (role, name, phone, address), Fees, Inspections, Conditions. The tabs and grids render client-side a moment later, so the client waits until each tab's "(N)" count equals the rendered rows, and re-opens once if not.
- The site-address link carries `ActivityNo=<permit number>`; every capture is checked against the permit that was clicked (no stale panels).
- A query returns **at most 100 rows**. A capped query is split by lot prefix (`46-365-1` ... `46-365-9`, then two digits, and so on). Probe on `46-365-` (141 reported): splitting recovered 139.
- The portal also returns **a few fewer rows than its own reported total even under the cap** (e.g. "returned 53 of 55"). Splitting does not recover them (children summed to the same 53). The per-block shortfall is recorded; 251 of 374 scoped blocks show one (3,548 records, mostly in cap-hit blocks before splitting).
- Gotchas found and handled: a new search keeps the grid's previous page index (it can open on page 2 of 2), so the client always jumps to page 1; a stale grid lingers after a new search, so the client waits for new contents; a permit with no PARID has an empty column.
- Data quirks: **Job Description is empty on all 25 pilot permits**; `CLOSED` permits show no Finaled Date (the close date is taken from the last completed *final* inspection); `OPEN` permits include legacy applications never issued (applied 1994, 2000) and a `1900-03-10` placeholder applied date, which is treated as no date.

## Scope decision (operator-directed, deliberate)

1. **Radius:** 1 mile around Hicksville (40.7684, -73.5251), unincorporated Town of Oyster Bay parcels only (SWIS 282489), whole section-blocks containing at least one parcel in the circle: **374 blocks, 7,091 parcels** (the earlier 3-mile scope of 1,424 blocks / 32,573 parcels is kept in `etrakit_scope_*_r3`). Coordinates: NYS centroid lat/lon, else GIS polygon point-on-surface.
2. **Exact count of every block** (count-only pass, 381 requests): **19,060 permits reported**; about 18,285 are capturable (cap-hit blocks recover about 96% by splitting; the portal's own shortfall is not recoverable). Estimated full cost 19,763 requests = **6.0-8.2 h** at 1.1-1.5 s per request: over the 5-hour limit.
3. **Cut:** blocks ranked by capturable permits (highest first) and taken while they fit a **11,000-permit budget** (a block that does not fit the remaining budget is skipped and a smaller one may take its place, so the cut-off is 38-52 permits rather than a sharp line). Result: **106 blocks included, 268 excluded**; **11,000 capturable permits, about 11,986 requests = 4.9 h at the measured 1.48 s per request** (3.7-5.0 h at 1.1-1.5 s). A 12,000-permit budget was tried first and measured 5.4 h, so it was reduced.
4. Every block, its counts and the include/exclude reason are in the DuckDB table `etrakit_scope_decision` (`rank`, `counted_total`, `counted_returned`, `capturable`, `est_requests`, `included`, `reason`); the exact counts are in `data/etrakit/block_counts.json` (gitignored). The harvest list is `data/etrakit/harvest_blocks.json`.

## Roofing classification, open/closed, and roof age

- `pipeline/permit_classify.py` classifies each permit with a **basis and confidence** (high / medium / low; medium or higher counts as roofing): job-description roofing words (strong: re-roof, roofing, shingles, tear-off, roof replacement = high; a bare "roof", or a solar/dormer/vent context = medium or low), permit type or subtype with ROOF, a contact role containing ROOF (medium), a non-owner contact name containing ROOF (medium for contractor/applicant), fee codes and inspection types containing ROOF (medium). Every basis is stored per permit (`etrakit_permit_facts.roofing_bases_json`). **Expect low yield**: job descriptions are empty in the pilot, so roofing is detected only from roles, names and codes.
- Derived fields: `is_open` (status OPEN/ISSUED/... or unknown; CLOSED/FINALED are closed; VOID/CANCELLED are void), `years_open` (open permits only; from the issue date, else the applied date labelled `applied_date_not_issued`; placeholder dates give no value), `past_expiration` (open with a valid expiration date before the as-of date), `close_date` with its basis. Unknown status words are flagged `status_known=false` and treated as open.
- **Roof age** (`property_roof_age`): the latest **closed** roofing permit linked uniquely to the property (event date = finaled date, else last completed final inspection, else issue date), labelled `roofing_permit_closed`; otherwise the NSI census-block estimate labelled `nsi_census_block_median_estimate` (low confidence); otherwise `unknown`. Open roofing permits are counted separately. A roofing keyword or an open permit alone is not treated as a completed replacement.
- Permit to property link by exact section-block-lot (`etrakit_permit_property_link`); permits with no match are listed in `etrakit_unmatched_sbl` with the reason (pilot: 25 of 25 linked uniquely; first two harvest blocks: 107 of 109, 2 unmatched).

## Identity baseline

`county-permit-adapter` says not to harvest before the identity baseline is loaded. The NYS DOS corporations are loaded; the Nassau Consumer Affairs licence list is not. Contacts are captured **raw only**; no company, person or licence is stamped from portal names.

## Run history and checkpoints

- Per-block checkpoint JSON in `data/etrakit/blocks/` (rewritten after every permit); raw scrubbed HTML per permit and per result page with sha256 in `data/raw/oyster_bay_etrakit/<run>/manifest.jsonl` (source URL is the portal page plus a `#search=...|page=...|permit=...` descriptor, since every view is a postback).
- Every 20 blocks (and at the end, or when stopped or blocked) the harvester loads new/changed block files into DuckDB with content-hash change detection and writes **one `pipeline_runs` row per batch** (`<harvest run>-bNNN`: new/changed/unchanged permits, record counts, status vocabulary, limitations). Partial batches never tombstone rows.
- A transient failure restarts the harvest (resuming from the checkpoints) after a growing pause; a captcha/403/block/lockout or login problem stops it for good and is recorded in `data/etrakit/status.json`, the log and the batch row.

## Commands

```
cd <repo>
.venv/bin/python -m pipeline.etrakit_harvest status        # alive?, blocks done, permits, requests, ETA
tail -f data/logs/etrakit.log                              # live log
cat data/etrakit/harvest.pid                               # pid file
.venv/bin/python -m pipeline.etrakit_harvest stop          # graceful: finish the permit, checkpoint, load a batch, exit
.venv/bin/python -m pipeline.etrakit_harvest start         # (re)start, detached; resumes from the checkpoints
.venv/bin/python -m pipeline.etrakit_harvest reparse       # re-parse saved raw HTML offline
.venv/bin/python -m pipeline.etrakit_load                  # merge any new block files now (needs the DB free)
```
